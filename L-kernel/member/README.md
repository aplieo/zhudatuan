现有实现位置：

- 节点与父链模型：`01_core_hexin/packages/config/src/SflNodeKernel.ts`。
- L6～L11 会员节点注册：`organization.register_hosted_member_node` 数据库函数及现有身份注册调用。
- 商城会员目录、详情及其他接口：`01_core_hexin/services/commerce/src/modules/member/`。
- 目录 SQL：`../../01_core_hexin/services/commerce/src/modules/member/04_adapters_shixian/persistence/MemberDirectoryQuery.ts`；现有服务的 `MemberDirectoryReader.ts` 只做数据库调用，尚未迁入内核。

目标中的第一个共用业务切片是会员的登记、所属节点与父链、档案和本店会员关系；目标是让 L0、L1、H6 复用同一实现，并分别验证各自的 Realm 和数据库绑定。**当前不能据模拟测试认定 H6 已独立继承。** OP、手机／微信登录、订单和四流状态不混进会员核心。MB 全域码只作身份展示，真实关系继续使用完整 ID。

讨论结论、尚待核对的边界与逐文件迁移清单见 [讨论记录与迁移地图](WORKING_AGREEMENTS.md)。MB 码目标是全域 ST 号段四位＋会员原归属店尾号四位；当前**只有纯规则**，不把它写成已分配或已上线的事实。

目前会员注册已能创建独立 Realm／节点，但不能据此认定“每个 MB 独立物理数据库”已经落地。此项需要单独的节点数据库开通与本店目录投影接线，不能靠复制会员 SQL 完成。
