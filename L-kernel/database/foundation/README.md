# L-kernel 数据库第一片：结构提取中

Ethan 当前决定：L-kernel 母库**暂不存实例**。这里仅安装可复制的标准结构和共用数据库规则；具体 L 的 Realm、Node、Membership、OP／MB、会员档案、订单及已分配号码记录均留在各自服务器，不作为母库种子。全域唯一发号若需运行时账本，须与本可复制母版分开处理，不把账本复制给每个 L。

L0～L5 各自的运行数据库跟随各自服务器部署；L-kernel 的 Supabase 项目不是这些节点的共享运行数据库。首次继承安装母版结构，后续应用版本化迁移，不用母版覆盖节点现有数据。

这个边界适用于所有 L：任何 L 的运行实例都不放在 L-kernel。L-kernel 汇集可复用源码、数据库结构、共用规则、标准模板和可复制的静态基准数据；具体 L 的配置绑定与业务记录属于该 L 的运行环境。需要全域唯一的一份动态账本（例如已分配号段）不能当作静态模板复制，须与可复制母版明确分开。

Ethan 已确定：全员 L 等级的**编码标准**应放进 L-kernel 数据库，作为可复制的静态基准；某个节点或会员的当前等级仍是各 L 的实例事实。现有解析源为 `L-kernel/src/node/SignedLevel.ts`，原数据库 `organization.noderelation.signed_level` 另有格式约束，迁入时需保证同一套定义，不额外制造第二份等级权威。当前解析器和数据库约束均接受未限定下界的负数等级；在静态目录确定具体负等级范围前，不暗中改变现有运行行为。

`20260918000000_copyable_identity_node_structure.sql` 是从桌面正本的 314 份现有迁移在一次性 PostgreSQL 17 空库重放后的实际结构，机械提取出的 **7 张表**：`identity.principal`、`identity.realm`、`identity.account`、`member.profile`、`access.membership`、`organization.node`、`organization.noderelation`。保留原有列、普通约束、外键和索引；没有复制 L0/L1 种子或业务记录。它是第一片的结构草稿，**尚不是可供节点运行的完整母版，也尚未安装到 Supabase**。

本地验证：原迁移 `314/314` 重放通过；结构草稿在另一空库执行通过，七表均为空。所选表的列、普通约束、外键和索引与重放后的原库一致。两者当前差异是原库的三个 Owner 专属约束触发器；这些节点专属逻辑不进入共用结构。

安装前还需从原实现切出与本片相配的共用父链版本校验、闭包更新，以及现有角色和 RLS 接线。当前 `access.membership` 仍混有 OP 字段和 OP 唯一索引；机械提取保留了这一事实，但它尚不符合 OP 与 L-kernel 平行的目标。原库同时挂有主打团 Owner、资格初始化等节点/业务触发器，不能将整段运行接线照搬到母库；也不能省略现有保护后宣称可以供生产节点继承。下一步逐项核对原函数、调用者与依赖，再验证可运行的第一片。不要用本草稿替换既有迁移或在 L1 上执行。
